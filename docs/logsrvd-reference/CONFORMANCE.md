## Priority findings

> **The single highest-value fix is the idle-timeout default.** Three requirements in this list (`ARCH-024`, `ARCH-045`, `CONF-025`) are the same defect, reached independently from two subsystems. The chain, verified end to end in the reference sources:
>
> 1. `plugins/sudoers/defaults.c:610` — `def_ignore_iolog_errors = false` **by default**.
> 2. `plugins/sudoers/log_client.c:1919-1921` — on a log-server read failure the client calls `loopbreak()`, commented *"Break out of sudo event loop and kill the command."*
> 3. `logsrvd/logsrvd.c:1372` — the C server arms **no** read timeout: *"No read timeout, client messages may happen at arbitrary times."*
> 4. `internal/connection/handler.go:202-203` + `internal/config/config.go:136` — Go arms a **10-minute** read deadline by default.
>
> A user idle for 10 minutes at a `sudo -s` prompt therefore has the connection dropped and **their running command killed**. `idle_timeout: -1s` opts out; note that `idle_timeout: 0` silently restores 10m rather than disabling it.

No requirement survived the adversarial pass at `breaking` or `high` severity.
